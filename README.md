# HW-1: микросервис, мониторинг и фоновая нагрузка

Микросервис на Java 25 и Spring Boot. Записи хранятся в `ConcurrentHashMap`,
идентификаторы выдаются атомарным счётчиком. Обновление существующей записи атомарно.
После перезапуска данные теряются; каждый экземпляр сервиса имеет собственное хранилище.

## Запуск
```sh
cp .env.example .env
docker compose up
```

## API
| Метод и путь | Результат |
| --- | --- |
| `POST /items` | `201 Created`, запись и заголовок `Location` |
| `GET /items/{id}` | `200 OK`, запись; `404` для неизвестного id |
| `PUT /items/{id}` | `200 OK`, заменённая запись; `404` для неизвестного id |
| `GET /health` | `200` и `{"status":"UP"}` при готовности, иначе `503` |
| `GET /metrics` | `200`, метрики в формате Prometheus |
| `GET /handlers` | `200`, список `{method, path}` для генератора дашборда |

## Метрики

Мониторинг построен на стандартном servlet-фильтре наблюдений Spring MVC и
Micrometer из Spring Boot Actuator.
### Метрики и лейблы

| Метрика | Значение |
| --- | --- |
| `http_server_requests_seconds_bucket` | Кумулятивные бакеты длительности запросов в секундах, граница в лейбле `le` |
| `http_server_requests_seconds_count` | Число завершённых запросов, включая ошибки; используется для RPS и ошибок |
| `http_server_requests_seconds_sum` | Суммарная длительность запросов в секундах |

Настройки в `.env` или окружении хоста:

| Переменная Compose | По умолчанию | Назначение |
| --- | --- | --- |
| `LOAD_START_RPS` | `1` | Начальный суммарный RPS |
| `LOAD_TARGET_RPS` | `30` | Суммарный RPS после разгона |
| `LOAD_RAMP_SECONDS` | `180` | Длительность разгона |
| `LOAD_RUN_SECONDS` | `0` | Длительность прогона; 0 — без ограничения |
